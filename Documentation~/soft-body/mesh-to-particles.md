# 从任意网格到质点：粒子生成与焊接的真实做法

> 一句话结论：**没有八叉树**。焊接用的是**均匀空间哈希**（uniform spatial hash，格边长 = `weldTolerance`），
> 每个候选再做一次精确的平方距离比较。这一页把代码里实际发生的事逐条写清，包括它的失败模式和实测数据。

对应实现：[`Runtime/SoftBody/SoftBodySimulation.cs`](https://github.com/opoi375/com.opoi375.physics-simulation/blob/main/Runtime/SoftBody/SoftBodySimulation.cs) 的
`Build()` / `FindWelded()` / `InsertIntoBucket()` / `CellKey()`。

---

## 1. 三步流水线

```text
网格顶点 + 三角形索引
      │
      ├─ ① 按位置焊接       顶点 → 质点（_weldMap: 顶点下标 → 质点下标）
      ├─ ② 抽棱建约束       三角形边 → 结构弹簧；共边两侧的对面顶点 → 弯曲弹簧
      └─ ③ 闭合性与体积     每条棱恰好被 2 个三角形使用 ⇒ 闭合 ⇒ 用散度定理算有向静止体积 V₀
                                  不闭合 ⇒ 体积约束被【静默跳过】
```

`SoftBodyMeshData` 只是"顶点数组 + 三角形索引"这个载体，不依赖 `Mesh`、`MonoBehaviour` 或物理引擎，
所以整条流水线在纯逻辑层就能被单元测试逐位断言。

---

## 2. 焊接到底怎么做的

按顶点数组的**原始顺序**逐个处理，每个顶点 `p`：

1. **算格坐标**（格边长就是容差）：

   ```csharp
   int cx = Mathf.FloorToInt(p.x / tolerance);   // tolerance = parameters.weldTolerance
   ```

2. **探查 27 个邻居格**（本格 + 各轴 ±1）：

   ```csharp
   for (dx = -1..1) for (dy = -1..1) for (dz = -1..1)
       if (buckets.TryGetValue(CellKey(cx+dx, cy+dy, cz+dz), out bucket))
           for (int b : bucket)
               if ((welded[b] - p).sqrMagnitude <= tolerance * tolerance) return b;   // 命中即复用
   ```

3. **没命中就新建质点**，并把这个质点下标塞进**它自己那一格**（注意：只插自己所在的 1 格，不是 27 格）。

4. `CellKey` 是三个质数系数的混合，`unchecked` 下的 `long`：

   ```csharp
   long h = (long)x * 73856093L ^ (long)y * 19349663L ^ (long)z * 83492791L;
   ```

**为什么 27 格正好够、也不多**：若两点距离 ≤ 容差，而格边长 = 容差，那么它们在任一轴上的格号最多相差 1。
所以"该找到的邻居"一定在 27 格里，而 27 格是能覆盖半径为格长的邻域的最小立方体邻域。

**格号冲突不影响正确性**：`CellKey` 是哈希，不同格可能撞进同一个桶。桶里存的是质点下标，
命中前还要过一遍 `sqrMagnitude <= tolerance²` 的精确判定 —— 冲突只会多比几次，不会把远处的点焊错。

**确定性**：`FindWelded` 是"第一个命中就返回"。当 `p` 同时落在两个彼此相距 > 容差的已焊质点附近时（链式重叠），
选谁当代表取决于遍历顺序与桶内的插入顺序。这两者都是固定的，所以同一输入永远得到同一套质点 ——
测试里逐位比较才成立。代价是**焊接不是等价关系**（A~B、B~C 但 A≉C 是可能的）。

## 3. 为什么是哈希而不是八叉树

| | 均匀空间哈希（当前实现） | 八叉树 |
|---|---|---|
| 需要的先验信息 | 无（边遍历边建） | 要先扫一遍包围盒，还要定深度上限 |
| 分布退化时 | 无影响 | 薄壳 / 长条网格会一层层压不下去，退化成线性 |
| 插入成本 | 均摊 O(1)，无递归 | 每次插入可能触发分裂 |
| 确定性 | 由固定遍历顺序天然保证 | 分裂/重平衡顺序是新的依赖源 |
| 精度 | 判定本来就是精确距离比较，树**只减少候选**，不改变结果 | 同左 —— 也就是说树买不到任何精度 |
| 代码规模 | ~40 行、无递归、一个 `Dictionary<long, List<int>>` | 节点结构 + 递归 + 深度策略 |

关键判断在最后两行：**结果精度和树无关**，因为最终裁决是一次 `sqrMagnitude` 比较。
树只影响"候选数量"，而哈希桶里的候选数量已经 ≈ 局部密度 × 容差³。

八叉树**才开始值得**的情形：单个格子里挤进成千上万个顶点（容差远大于特征尺寸的极端过焊设置）。
这时哈希桶退化成线性扫描。项目网格没有落进这个区间（实测焊接比中位 3.00，见下页）。
**需要说清的是：桶内候选数本身没有单独埋点测过**（那要给哈希插桩），所以这一页只回答"什么情况下需要换结构"，不宣称"当前实现已经测过很快"。

## 4. 容差的真实语义（三条测试盯的就是这个）

`weldTolerance` 是**半径**，不是直径，也不是"格子大小的提示"。它的三种后果都被
[`SoftBodySimulationTests`](https://github.com/opoi375/com.opoi375.physics-simulation/blob/main/Tests/Editor/SoftBodySimulationTests.cs) 钉住：

| 情形 | 结果 | 测试 |
|---|---|---|
| 顶点**完全重合**（FBX 接缝的常态） | 任何正容差都焊得上，质点数 = 真实角点数 | `Weld_CoincidentVerticesMergeEvenAtTinyTolerance`（1e-6 容差下 24 顶点仍焊成 8 质点） |
| 缝隙 ≤ 容差 | 焊上，拓扑闭合，体积约束生效 | `Weld_ToleranceIsARadius_...`（0.01 缝 + 0.02 容差 ⇒ 8 质点、闭合、V₀ ≈ 1） |
| 缝隙 > 容差 | **裂成两套质点 ⇒ 拓扑不闭合 ⇒ 体积约束被静默跳过** | 同上（0.01 缝 + 0.005 容差 ⇒ 12 质点、不闭合、`RestVolume() == 0`） |

第三行是实务里最贵的坑：模型看起来是"闭合的盒子"，但因为美术在导出时把缝拉开了一点点，
它跑起来**完全没有体积回弹**，只是一袋弹簧。数值上不会报错，只有扫描报告的 `OpenMesh` 判定能看出来
（[模型实测](/soft-body/model-audit) 里项目有 11 个网格正是这一类）。

**怎么定容差**：

- 下限：≥ 你所能容忍的最大接缝缝隙。默认 `1e-4` 米（0.1 毫米）只适合**顶点严格重合**的资产。
- 上限：≤ 模型最小特征尺寸的 1/3。再大就会把本该分开的两个角焊成一个，导致包围体积虚增甚至退化。
- 检查手段：跑一次 `Tools/Physics Simulation/Soft Body/Audit Selected Meshes (123)`，看 `weld x`（焊接比）
  与 `closed` 两列。焊接比明显低于同类资产 + `closed = no` ⇒ 容差够不到缝。

## 5. 真正的精度墙：float 分辨率，不是格坐标溢出

一个曾被写进设计草案的假设是："格坐标 = 坐标 / 容差，而 `CellKey` 收 `int`，
所以大坐标 + 小容差会溢出 32 位、焊接静默失效，应当加护栏。"

**这条假设被测试推翻了**，而且推翻的方式更有用：

- float 在量级 `|c|` 处的间隔约为 `|c| · 2⁻²³`。`c = 1e7` 时间隔约 1.2 米，`c = 5e7` 时间隔约 6 米。
- 于是把一个 1 米立方体挪到 `x = 5e7` 米处，它的棱在 float 里**根本表示不出来**：
  顶点塌成同一点 ⇒ 三角形面积为 0 ⇒ 构建阶段直接被拒（异常消息：`三角形 0 面积为 0（三点共线），体积梯度会失效`）。
- 而在"坐标还没大到丢精度"的区间里，重合顶点即使格号溢出也仍然落进**同一个桶**（同样的输入 → 同样的溢出结果），
  照样能焊；不重合的顶点又因为缝隙小于该量级的分辨率而变成"重合"。

结论：**哈希的 int 格坐标在 float 允许出错之前不会先出错**，所以没有为它加投机护栏，
只把上面这条真实契约钉进了测试（`Weld_MeshFarFromOrigin_IsRejectedWithAClearGeometricError`）。

实务规则因此很简单：**把软体放到靠近世界原点的位置**。`SoftBodyBehaviour` 本身在本地空间模拟，问题只出在网格顶点自带几十公里的导入偏移上。换算依据是 float 在量级 `|c|` 处的间隔约 `|c| · 2⁻²³ ≈ |c| · 1.19e-7`：

| 想保住的特征尺度 | 坐标量级上限 |
| --- | --- |
| 1 毫米 | ≈ 8.4e3 米（此时 ulp ≈ 1 mm） |
| 1 厘米 | ≈ 8.4e4 米 |
| 1 分米 | ≈ 8.4e5 米 |

## 6. 构建阶段的拒绝清单

`Build()` 不会为了"跑起来"而容忍坏几何，以下情形一律抛 `ArgumentException`（消息为中文、点名参数）：

| 拒绝条件 | 为什么 |
|---|---|
| 顶点数组为空 / 三角形索引为空或不是 3 的倍数 | 无法构建 |
| 顶点含非有限值（NaN / Infinity） | 一个 NaN 会污染整条弹簧链 |
| 三角形面积为 0（三点共线） | 体积梯度 ∇ᵢV 由面积向量累加，共线三角形给出零向量 |
| 焊接之后三角形退化（三点落到同一个质点或共线） | 同上，且消息里会点名是第几个三角形、当前容差是多少 |
| 参数非法（质量 ≤ 0、容差 ≤ 0、`maxStretchRatio` < 1 等） | `SoftBodyParameters.Validate` |

这些拒绝在扫描报告里显示为 `BuildFailed`，**note 列带上原因原文**（例：
`三角形 83 在焊接容差 0.0001 下退化成一条线，请缩小 weldTolerance 或简化网格`）。

## 7. 项目 104 个真实网格上的焊接实测

| 指标 | 实测 |
|---|---|
| 焊接比 `网格顶点数 / 质点数` | 中位 **3.00**，最高 **5.00** |
| ⇒ 含义 | 美术网格大约 **2/3 的顶点是重复引用**，焊接不是优化而是必需品 |
| 质点数 | 中位 **67**，最小 0（构建失败），最大 576（预算线内） |
| 拓扑闭合 | **91 / 104 = 87.5%** |
