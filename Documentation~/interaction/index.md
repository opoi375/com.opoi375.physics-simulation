# 多体质点互碰（Particle Interaction）

v1.6.0 之前，三个求解器各自为战：软体只跟场景 Collider 打交道，布料也是，两个体叠在一起会直接互相穿过。
v1.6.0 加了一条**体与体**的接触通道。

## 怎么用

挂一个 `ParticleInteractionGroup`，再用 `group.Add(body)` 把要互相碰的体交给它；或者在每个体自己的 Inspector 上填 `interactionGroup`
（体在每步的 `SyncColliders` 里惰性入组：“拖了组但没人调 `Add`”是最常见的用法）。两条路走的是同一个入口 `Add`，
所以不会出现"组里记了名、体自己不知道"。`Members` 是只读视图（登记顺序 = 加入顺序），给演示工具与测试用。

```csharp
var group = gameObject.AddComponent<ParticleInteractionGroup>();
group.Add(jellyA);      // SoftBodyBehaviour
group.Add(jellyB);
group.Add(scarf);       // ClothBehaviour —— 跨求解器不需要任何额外配置
```

**没有成员 = 已发布行为逐位不变**。这是刻意设计的：互碰是显式登记的，不存在"自动全场互碰"这种隐藏全局状态。
流体不参与互碰（它是粒子云，与这边的球云是两套东西）；互碰只在软体 / 布料 / 质点弹簧三个求解器之间发生，
因为只有它们实现了 `IParticleBody`。

## 接触几何：球云，不是三角面

每个体把自己的质点当成**一朵球**交给别人。为什么不用贴合的三角面：深穿透时"最近面"的法向会翻，那是 v1.5.0 水箱踩过的角部传送带坑；球云没有方向歧义，代价是接触面有颗粒感。

关键一条，**它和直觉相反**：

> 接触判定距离 = **对方半径 + skin**，不是 `r_A + r_B`。

因为一个体的质点在代理眼里是**点**，不是球。所以两个表面要先互相吃进去大约"半个质点间距"，互碰才会真的参与。

## `cloudRadiusFactor`（半径系数）

| 求解器 | 默认 | 半径来源 |
|---|---|---|
| 软体 | 0.5 | 平均结构静止长度 × 系数，再被静息尺度钳住 |
| 布料 | 0.5 | `spacing` × 系数 |
| 质点弹簧 | 1.0 | `particleRadiusBase` × 系数（它本来就是绝对半径，1.0 才不改已发布外观） |

0.5 的含义是"相邻两个球刚好相切"。实测（0.6 m 方块、sub=3、零重力、两个体摆成面间隙 0.08 m、跑 360 步）：

| 系数 | 半径 | 判定距离 | 总平移（360 步） | 结果 |
|---|---|---|---|---|
| 0.25 | 0.057 | 0.067 | 0 m | **完全没反应**：最近球心距 360 步一直冻在 0.080 m，速度精确为 0 |
| 0.35 | 0.080 | 0.090 | 1.64 m | 分开，但判定距离已小于质点间距 0.228 ⇒ 会从缝隙里漏 |
| **0.50** | 0.114 | 0.124 | 3.78 m | 默认 |
| 0.75 | 0.150 | 0.160 | 4.02 m | 两团还差半个间距就互推，弹得更狠 |

系数调小不是"接触更精细"，是**直接漏接触**。想让接触贴合，正确做法是**加密网格**（sub=3 → 6 把间距 0.228 砍到 0.114），不是调小半径。

半径另外还有一条静息尺度上界 `cbrt(静息体积) × 0.25`：稀网格 + 大系数会把球云吹成比身体还大的气球，那样两个体永远解不开自己的重叠。

## 已知限制（都是量出来的）

**等重的两个体堆不住。** 四档刚度配方跑下来，终点全是"两个体并排躺在地上"（最近球心距 0.58–0.91 m）。原因是契约本身：每个体把自己从对方里投影出去，谁也不让谁，而退出方向带着侧向分量，上面那个必然滑下坡。**轻压重是可以的** —— 演示场景里那条布就实实在在被果冻托着，因为能动的只有布的质点。

**深互插会产生一次性回弹，而且削不掉。** 演示场景原来摆成重叠 0.18 m（≈一个质点间距），实测两个体总平移 4.61 m（系数 0.5），**但是衰减的**：每 60 步位移 1.03 → 0.18 m，不是发散。

我们照 v1.5.0 流体 `maxSpeed` 的经验给每次查询加了"最多补 25% need"的上限，然后**实测它无效**：4.61 → 4.15 m，系数 0.75 那档反而从 4.53 变成 5.65 m。原因是弹性能存在**弹簧与体积约束**里，不在"某一步搬多远"里 —— 一个被压扁 28% 宽度的果冻反弹出去，那是真物理。于是这套机制**撤回**了，没有作为未经验证的 API 留在包里；演示场景改成面间隙 0.06 m 起手（仍在 0.105 m 判定距离之内，所以互碰照样有东西可演，但不再弹飞）。
